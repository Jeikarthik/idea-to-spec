## Core principles

### I. Engineering standards
SOLID as the default code-quality bar. Clean separation of concerns: small focused modules with
explicit interfaces. No cross-module reach-through.

### II. Verification before done
Every requirement carries a Given/When/Then acceptance criterion and names the gate that verifies it.
Nothing is marked done until that gate passes.

### III. Secrets discipline
Secrets only via `.env`/proper secret management. Never hardcoded, never committed. `.env.example`
carries key names with empty or placeholder values.

### IV. Migration safety
Migrations are ordered, commented, and reversible where practical; irreversible ones say so explicitly.

### V. Evidence over elegance
Changes that contradict the validated problem in `backbone/master-prd.md` §1 are rejected, however
elegant. Conflicts are surfaced, not reconciled silently.
